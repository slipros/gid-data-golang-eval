# GID-247 `gidconvpolicy` — расширение: enum-константы, выбираемые не-enum условием

## Постановка

Правило «в конвертере нет бизнес-политики» судило только выбор **базовых (неименованных)** констант.
Именованные enum-константы были исключены намеренно («enum→enum mapping is GID-143/233 territory»), и
исключение проглотило ровно тот дефект, ради которого правило заводилось (consent-webhook-trigger:
`WebhookTriggerV2EmptyReason` выбирается по `len(UserIdentifiers) == 0` и `len(identifiers) == 0 && len(source) > 0`).

## Решение: расширение GID-247, НЕ новый ID

Оставил **тот же GID-ID в том же линтере**. Обоснование: отдельный ID оправдан, когда у поведения
своя граница и свои исключения (как GID-261 рядом с GID-260). Здесь поведение одно — «конвертер
принимает бизнес-решение», слой тот же (`convert`), исключения те же (`//nolint:gidconvpolicy`,
`settings.exclude`, generated, `_test.go`), фикс тот же («перенести решение в `/domain/model`»).
Изменился только критерий детекции, и это не добавление новой границы, а сужение слишком широкого
исключения. Заводить новый ID значило бы дублировать реестр, конфиги и исключения ради одной формулы.

Критерий — по тому, **что читает условие**, а не по типу выбираемой константы:

- условие читает только enum-типизированные значения (`switch` по enum-выражению, сравнение с
  enum-константой) → enum→enum mapping, правило молчит (GID-143/233);
- условие читает хоть одно не-enum значение (длина, пустота/nil, bool-флаг, сравнение чисел/строк,
  вызов предиката) → при выборе ≥2 различных констант **одного** именованного enum-типа — нарушение.
  Смешанное условие (enum И не-enum) — не отображение, судится;
- базовые константы сохраняют прежнее, более широкое поведение: судятся в любой ветке по параметру,
  независимо от того, читает ли условие enum.

Прочие границы сохранены: только последний сегмент пути `convert`; одна и та же константа во всех
ветках — не выбор; ветвление по локальной переменной — не судится; одиночные константы без ветвления —
не судятся. Новое: `_test.go` не судится (GID-250, `internal/srcfile.IsTest`) — раньше файлы не
фильтровались вовсе; тест-дабл, воспроизводящий форму инцидента, — скаффолдинг.

Технические детали реализации:
- перечисление `FuncDecl` переведено на `internal/astwalk.NodesOf` (+ `Requires: astwalk.Requires`),
  добавлен skip generated/`_test.go`; внутренние обходы тел функций остались на `ast.Inspect` —
  согласно конвенции («walk, суженный до одного тела функции, остаётся на ast.Inspect»);
- читаемость условия определяется по типам подвыражений (`go/types`): именованный тип → enum-чтение,
  всё остальное (basic, slice/ptr/map/struct/interface/chan, вызов предиката) → не-enum чтение.
  Собственно результат сравнения/логической операции (`==`, `&&`) чтением не считается — судятся его
  операнды, иначе `source == SourceMeeting` давал бы ложное «не-enum чтение» через тип `bool`;
- enum-константы группируются по именованному типу (выбор — внутри одного enum, не между типами);
  в зачёт идут присваивания в ветках с не-enum условием, а дефолтное (вне-веточное) присваивание
  участвует в подсчёте различий — именно это ловит форму инцидента, где первая константа стоит
  вне ветки.

## Осознанно оставленное

- `else`-ветка наследует вердикт условия `if` (пара — одно решение); для `else if`-цепочки внутренний
  `if` даёт собственный span — форма зафиксирована фикстурой `ReasonFromKindIf`.
- Вызов предиката в условии судится (задано постановкой), даже если предикат — чистый enum→bool из
  `/domain/model`; каноничный фикс — передавать конвертеру готовый результат без ветвления.
- Смещённый подсчёт различий: различия считаются по всем присваиваниям переменной (включая
  enum-driven ветки), а не только по не-enum веткам — симметрично действующей логике для базовых
  констант.
